# Contributing to Cybercore Tech

Cybercore is built in public. Contributions are welcome across code, tests, documentation, design, accessibility, issue triage, and release quality. You can contribute without applying to the core team.

## Start here

1. Read the repository README and any project-specific contribution notes.
2. Search existing issues and pull requests before starting a substantial change.
3. For a larger feature, open an issue or discussion first so the direction can be agreed on.
4. Fork the repository, create a focused branch, and explain the change in a pull request.
5. Run the checks documented by that project and include the results in your pull request.

Small, reviewable changes are easier to discuss and merge. Include tests and documentation when they help explain or protect the behavior. Follow the repository's license and only submit work you have the right to contribute. Never commit passwords, API keys, tokens, private data, or generated files that the project does not track.

Be respectful, describe disagreements clearly, and make room for contributors with different experience levels. A résumé or minimum number of years is not required. See the [Cybercore Dev Team page](https://cybercoretech.net/dev-team/) for current contribution areas and the optional private application form.

## Security reports

Do not post vulnerability details in an issue or contributor application. Report security concerns privately to [security@cybercoretech.net](mailto:security@cybercoretech.net), following the repository's `SECURITY.md` where available.
